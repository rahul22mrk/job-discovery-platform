# Target Users

## Primary Users

The first version is for people who are actively looking for upcoming walk-in drives.

A typical user may:

- Search for jobs in a specific city
- Look for a particular technology or role
- Have a specific experience range
- Want to find opportunities happening in the coming days or weeks
- Spend time checking multiple websites and job posts
- Want to avoid expired, duplicate, or irrelevant postings

## Example

A user wants:

- City: Bengaluru
- Technology: Java
- Experience: 3–5 years
- Date: Next 30 days

Instead of searching different websites manually, the user should be able to enter these details and get relevant upcoming walk-in opportunities in one place.

## Search

The initial search will provide:

- City
- Technology / Role
- Experience
- Date range

Technology and role can be selected from predefined options to improve search quality.

Users should also be able to enter their own keyword if the required option is not available.

Example options:

- Java
- Spring Boot
- React
- Python
- QA
- DevOps

Custom keywords should also be supported, such as:

- Kafka
- SDET
- Salesforce
- Machine Learning

## Future Users

The platform should not be limited to walk-in job seekers.

Later, the same platform can support people looking for:

- Regular job openings
- Jobs from a specific company
- Hiring drives
- Jobs for a specific technology
- Jobs in a specific location
- Job alerts
- Company tracking

These features are outside the initial V1 scope.

## User Experience

The product should be:

- Simple to use
- Easy to search
- Clear about where the information came from
- Clear about how recent the information is
- Free from unnecessary duplicate results
- Useful without requiring complicated filters

The basic flow should be:

Search
↓
Relevant Opportunities
↓
Check Details
↓
Check Original Source
↓
Apply / Attend

## Main User Problem

> Finding relevant and upcoming hiring opportunities should not require searching multiple websites again and again.
